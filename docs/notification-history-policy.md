# 微信通知历史与最后回复展示

## 已确认的行为

- 设置名为“显示你最后回复的消息”，默认关闭；适用于模块通知栏回复，包括连续发送的一组回复。
- 对方来信 A → 通知栏回复 B → 对方来信 C：默认显示 C，开启后显示 B+C；后续 D 分别显示 C+D 或 B+C+D。
- 通知栏回复成功按已读处理：清理该次回复所对应的 A 及更早通知归档。B 使用新的显示代次保存；回复失败不清理。
- 已确认点击移除、单条划除或清空通知，只清理对应代次及其前驱；保留晚到的新来信、其他会话及联系人身份缓存。
- 普通更新、应用自行取消、listener cancel、超时或单纯查询不到活动通知，不推断为用户已读。发布补图或回复刷新前仍须确认目标通知实际存在且代次匹配。
- 开关参与后续正常通知构建；不保存每轮的开关副本，不主动重建旧通知，不补回已经裁掉的本人消息。
- 已读/划除清理对两个开关状态都生效；开启开关也不能恢复已结束通知中的旧 B。

## 实现边界

`ConversationRound` 继续维护回复 UUID 与待回应/已回应状态。开关只控制已回应回复的展示；待回应回复和重复回调识别保持独立。`EXTRA_REMOTE_INPUT_HISTORY` 仅保留待回应回复，不因展示 B 而再次静音 C/D。

每条模块消息携带其所属显示代次。确认清理后，归档删除匹配代次及其前驱；后续快照以已读边界过滤继承的旧消息，避免只删旧条目却留下新快照中的 A。成功的连续回复会把仍待回应的同组本人消息带入新显示代次；派发时保留该组 UUID，C 先于成功回调到达也不拆散该组。边界和消息代次随 Parcel、图片样式与通知重建保留，不使用正文、时间接近或消息位置猜测删除对象。

微信进程为聊天通知包装不可变、逐代次的 `deleteIntent`。私有动态接收器先执行本地缓存清理，再转发微信原有已读 PendingIntent；单条划除和清空不依赖 SystemUI 的重置广播。点击仍沿用现有 SystemUI 移除事件。两条路径重复到达时安全忽略已经清理的代次。

通知栏回复在派发前记录对应代次、会话实例和待回应组，成功回调后清理该代次，保留期间到达的新消息并记录 B；原生和合成回复使用同一控制器入口。C 已经到达时直接确认 B 已被回应，并保留 C 的轮次归属，包括缺少时间戳的 C；下一条 D 不得再次裁掉 C。成功回复 UUID 的有限去重记录与展示历史独立。已被移除或换会话的通知不因迟到的回复回调重新发布。图片任务只取消属于已读代次的任务，保留新来信对应的图片。

应用内发送与迟到回复回调交错时，以应用内发送时的通知代次判断 C 是否已跨过该边界；跨过后丢弃边界前的本人回复，再确认边界后的回复组。C 无时间戳时仍能区分先后；C 之后才发生的应用内发送保留到下一次来信处理。
