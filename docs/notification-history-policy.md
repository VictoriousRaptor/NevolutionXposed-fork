# 微信通知历史与最后回复展示

## 已确认的行为

- 设置名为“显示你最后回复的消息”，默认关闭；适用于模块通知栏回复，包括连续发送的一组回复。
- 对方来信 A → 通知栏回复 B → 对方来信 C：默认显示 C，开启后显示 B+C；后续 D 分别显示 C+D 或 B+C+D。
- 收到有效的通知栏发送操作即按已读处理：清理该次回复所对应的 A 及更早通知历史，不等待回复结果。派发满足既有条件后才保存 B；失败不记录 B，但已读处理不撤销。
- 已确认点击移除、单条划除或清空通知，只清理对应代次及其前驱；保留晚到的新来信、其他会话及联系人身份缓存。
- 普通更新、应用自行取消、listener cancel、超时或单纯查询不到活动通知，不推断为用户已读。发布补图或回复刷新前仍须确认目标通知实际存在且代次匹配。
- 开关参与后续正常通知构建；不保存每轮的开关副本，不主动重建旧通知，不补回已经裁掉的本人消息。
- 已读/划除清理对两个开关状态都生效；开启开关也不能恢复已结束通知中的旧 B。

## 实现边界

已读与回复派发分别处理：验证通知 ID、输入和对应路径的必需元数据后，在派发前请求微信原生已读并清理模块历史。原生回复的 `resultCode=0` 或合成回复调用正常返回，仅用于本人回复历史与派发状态判断，不作为已读门槛。两者都不是微信网络送达回执。无原生已读目标、动作失效或内部异常时保留诊断；本地历史与原生已读分别尝试，异常不阻止后续回复派发。

`ConversationRound` 继续维护回复 UUID 与待回应/已回应状态。开关只控制已回应回复的展示；待回应回复和重复回调识别保持独立。`EXTRA_REMOTE_INPUT_HISTORY` 仅保留待回应回复，不因展示 B 而再次静音 C/D。

每条模块消息携带其所属显示代次。确认清理后，归档删除匹配代次及其前驱；后续快照以已读边界过滤继承的旧消息，避免只删旧条目却留下新快照中的 A。成功的连续回复会把仍待回应的同组本人消息带入新显示代次；派发时保留该组 UUID，C 先于成功回调到达也不拆散该组。边界和消息代次随 Parcel、图片样式与通知重建保留，不使用正文、时间接近或消息位置猜测删除对象。

2026-10-23：划除已读恢复上游实现，直接将微信 CarExtender 的 `on_read` PendingIntent 设为通知的 `deleteIntent`；没有车载扩展时保留原删除动作，不再经模块动态接收器转发。微信原生已读调用不依赖模块的本地历史清理。点击、单条划除和清空后的本地历史清理统一依赖既有 SystemUI 移除广播及通知代次校验；SystemUI hook 或广播不可用时，本地历史可能保留，但不会因此阻断系统发送原生已读动作。无原生 `on_read` 或原生动作失效时，不承诺微信已读。

通知栏回复在派发前记录对应代次、会话实例和待回应组，并立即建立已读边界；原生与合成回复使用同一已读入口。清理后保留不含已读来信的当前快照及既有待回应回复组，供成功回调记录 B；失败不伪造 B。通知移除仍能删除该快照，因此迟到回调不能复活用户已移除的通知。保留期间到达的新消息；C 已经到达时直接确认 B 已被回应，并保留 C 的轮次归属，包括缺少时间戳的 C；下一条 D 不得再次裁掉 C。成功回复 UUID 的有限去重记录与展示历史独立。图片任务只取消属于已读代次的任务，保留新来信对应的图片。

成功回调通过会话实例、代次与已读边界校验后，先按当前展示开关保存规范化回复快照，再独立决定是否重发活动通知。微信自行取消、listener cancel 或活动通知查询无匹配项不丢弃成功回复及去重 UUID；下一次正常来信继续使用已保存历史。用户确认移除已清空归档时，迟到回调仍被拒绝，不因保存快照而恢复通知。

应用内发送与迟到回复回调交错时，以应用内发送时的通知代次判断 C 是否已跨过该边界；跨过后丢弃边界前的本人回复，再确认边界后的回复组。C 无时间戳时仍能区分先后；C 之后才发生的应用内发送保留到下一次来信处理。

## 验证范围

- 单元测试：开关两种状态、待回应回复、去重、设置升级默认关闭和显式选择保留、归档按确认代次删除及计数。
- Android framework 仪器用例：C/B+C、连续回复、Parcel/Builder 重建、晚到清理保留 C/D、已读边界不复活 A，以及普通/媒体通知与重建后的删除动作保持微信原生目标、关闭装饰器后仍能直接发送。该用例不模拟进程死亡或验证真实微信未读数。
- 真机仍需分别验收：微信真实收发、点击、划除、清空、并发来信、图片补图以及声音/震动/浮动通知。本次源码与构建证据不能代替这些验证。
- 回复已读回归：原生非零回调/已取消 PendingIntent、合成返回 false/抛异常时仍请求已读且不记录 B；普通和媒体回复共用该行为。覆盖提前清理后连续回复组、迟到成功回调、无时间戳新来信及移除后不复活。框架用例以本地合成目标验证，不调用真实微信。
- 无活动通知回归：重发入口无操作时，仍保存连续成功回复、有限去重状态和晚到的新来信；两种展示开关下均检查后续 C/D。测试替身不再在重发入口缓存回复，避免掩盖保存依赖。该 framework 用例须在 Android 环境执行，编译通过不代表已经运行。
