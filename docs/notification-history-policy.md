# 微信通知历史与轮次

## 当前规则（2026-11-13）

- 对方第一条新来信开始一轮，同一联系人或群聊继续追加，最多显示 25 条。
- 通知栏收到有效发送动作时，按动作开始时捕获的会话实例与通知代次立即结束该轮，然后独立请求微信原生已读和派发回复。原生已读缺失、派发异常、非零结果或实际发送失败都不恢复旧轮；结果回调不保存本人正文或重发历史。
- 用户划除、清空和点击移除按原通知代次结束；点击后通知未移除但打开微信会话时，由微信实际已读事件结束。
- 微信本机已读和多端同步到本机的会话已读，由独立已读 observer 观察。完整版本与失败关闭规则见适配手册，不按通知消失、超时或任意 cancel 推断已读。
- 结束时退休旧归档，取消属于旧代次的头像和图片任务。系统当前卡片可以保留，下一条新来信仅显示新轮内容。结束操作捕获之后到来的 C 保留；若 C 在微信真实已读开始前已经到达并被该次操作一并读掉，则正常结束 C。
- 不监听微信发送状态、消息入库或重发，不再解析应用内本人回复正文；已删除“显示你最后回复”设置及待回应/已回应分组。旧偏好被迁移清理，旧快照中的本人行不再进入模块消息历史。

例如 A、B → 通知栏发送 → C → D，新的卡片依次显示 C、C+D。不存在跨轮的本人回复上下文。

## 身份、顺序与重建

- 每个会话只有一个单调结束代次。重复结束、晚到的旧回调不能推进到更新通知；会话实例替换后旧目标失效。
- 同会话、同发送者范围内的可信正值服务端 ID 只采用首次表示与首次通知代次。每会话保留最多 64 个身份记录，结束轮次不清空；会话替换或有界会话缓存淘汰时清理。该窗口独立于 25 条显示历史。
- 去重发生在认定新来信之前。已结束消息换新 token、时间或来源重投，不能重新开启一轮；不同 ID 的连续语音保持独立。缺失可信 ID 时继续采用原有保守 occurrence 合并，不按正文或语音短时间窗口猜测。
- 合并以通知代次排序，时间只用于显示；零、相同或回退时间不阻止新轮，容量裁剪保留最新代次。
- 结束后不整体导入原生结构化旧历史，只使用当前来信和可靠的新代次条目。模块快照、Parcel/Builder 重建、头像和图片补图、撤回提示都不能伪装新来信；早期已结束快照在发布入口也会被拒绝。
- 保留联系人身份、稳定 peer ID、群成员隔离、附件和撤回身份。补图重新读取当前活动卡片，不能恢复已退休历史。
- 新原始来信清除旧 RemoteInput 历史及其临时静音标志；补图和其他已规范化重建保留静默刷新语义。

## 验证边界

主机模型及 hook 合成回归与 Android framework 回归分别记录。framework 构建、签名或 hook ready 不能代替微信真实收发、多端已读同步、系统未读数、声音/震动和 OEM 通知外观验收。当前实现不增加按来信查询未读记录的兜底，也不承诺跨微信进程重启保留内存历史。

## 发送 UI 完成确认

通知发送处理在 finally 中独立尝试更新仍活动的原卡片，让系统复位输入和发送按钮；派发成功时将提交文本追加为当前卡片中的本人行，明确派发失败时仅复位 UI；这一步不恢复归档，也不撤销此前的结束代次。回显仅表示本地派发，不表示网络送达。新消息 C 已替换原目标、通知已移除或身份已改变时，不更新旧卡片。连续发送从仍活动的规范化卡片捕获新目标。新来信同时清理旧式/结构化 RemoteInput history 及 spinner/smart-reply 临时标记。详见适配手册 2026-11-13 后续 UI 确认章节。

完成资格同时要求本地发布状态匹配：C 已被模块接受或取消已被 BEFORE 回调观察时，即使系统仍返回旧 A，也不允许重新发布 A。tag 取消与 cancelAll 只撤销 UI 发布资格，不自行推进普通已展示消息的未读边界；提交结束归档后仍允许完成尚可见的原卡片。
