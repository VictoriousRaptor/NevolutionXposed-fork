# 微信通知头像与展开应用头

> 使用 writing-plans 记录本次明确需求，直接在当前干净工作区实施；不自动提交、安装或推送。

**目标：** 私聊使用微信原通知头像和系统会话模板的应用角标；提供默认开启、可关闭对比的展开应用名隐藏开关。

**实现选择：** 保留 MessagingStyle 的消息、身份、回复和轮次，在 framework 渲染入口选择原生 ConversationLayout 并传入微信原头像。链接、文件等已经使用微信原模板的通知沿用原图标。展开结果只隐藏应用名和它的分隔符，保留会话标题、时间、展开按钮及操作。

其他选择：自绘头像及角标会复制系统尺寸、遮罩和 OEM 规则；把私聊改成普通文本模板会丢失会话展示能力。本次采用系统已有的会话模板，不伪造快捷方式、不更改会话重要性或通知排名。

**边界：** 仅在微信主进程/SystemUI 已有作用域内，对带模块标记且实际包名为微信的消息通知生效。群聊不套用私聊头像规则；未知会话延续已有非群聊展示，类型确认后遵循实际类型。无原头像时保留系统回退。每项 hook 独立校验签名并失败回退，不新增微信混淆画像。图标尺寸及 OEM 视觉结果须另行真机验收。

## 重点复核

- Android 17 将展开入口改名为 createExpandedContentView；旧系统使用 createBigContentView。
- SystemUI 可重新绑定会话数据，应用名隐藏动作必须追加在最终数据绑定之后。
- 关闭开关不能复用已被修改的缓存 RemoteViews，因此输出修改前必须克隆。
- 图片自定义展开模板和媒体原模板也要保留标记，且不改消息、回复和撤回身份。
- 测试和构建不等于 LSPosed 安装、ColorOS 展示或真实微信消息验证。
