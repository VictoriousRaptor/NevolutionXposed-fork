# Debug 图片缩放对比

仅 Debug APK 增加独立的“图片缩放测试”桌面入口，页面和资源全部位于 `src/debug/`，不会进入 Release。复用现有 AppCompat，不增加依赖、不改变微信或 SystemUI hook，不修改生产图片预览、版本画像及 1.5 秒等待策略。

页面提供六项手动对比：保留方形 Lenna / 完整打码 Lenna 的 `fitCenter` / `centerCrop` 四项，末尾新增方形与完整图各一项 `fitStart`。`fitStart` 按原比例完整显示，并对齐图片区域左上边缘。页面内的图片区域统一为 160 dp 高，灰色底用于辨认留白；每项按钮以独立 ID 发出本地测试通知。通知使用 `DecoratedCustomViewStyle` 和对应缩放模式的 `RemoteViews` 展开布局，图片区域同为 160 dp 高；收起及正常横幅的正文显示 `[图片]`，手动展开显示图片。系统包装、实际宽度及可用高度可能与页面预览不同，应以设备通知为准。

图片提前在后台解码，加载成功后才显示测试按钮，不涉及网络或异步补图。首次发送请求通知权限；通知或测试渠道被禁用时引导设置。页面的“清除六项测试通知”仅取消这个测试渠道下约定 tag/id 的六条通知，不清除微信通知。没有自动发送、自动选择缩放模式或其他通知测试。

## 使用

1. 打开桌面的“图片缩放测试”。
2. 在页面中对比六项；分别点击“发送此项测试通知”。
3. 手动展开横幅或通知栏通知，观察 `fitCenter` 的完整图片与居中留白、`centerCrop` 的填满和裁剪，以及 `fitStart` 的完整图片与左上对齐。
4. 可使用页面底部按钮清除这六项通知。

此页面用于手动对比三种缩放方式。2026-10-21 生产微信图片通知已独立采用 `fitStart` 展开布局，详见适配手册；Release 不包含本测试页和素材。构建和安装不等于真实通知行为验收，实际效果由用户手动确认。

2026-10-20：3.3.0 / versionCode 15 Debug 构建通过，新包及安装前旧包的证书均与既有 release 证书一致。覆盖安装成功，回拉 APK 的 SHA-256 与本地交付副本一致；已确认测试 Activity 可解析，微信及 SystemUI PID 均未变化。未自动点击测试按钮或发送通知，未执行单元测试及仪器测试；实际页面与通知效果由用户手动验收。

同日新增两项 `fitStart` 后再次完成 Debug 构建、release 证书核对、覆盖安装和回拉哈希核对；微信及 SystemUI PID 保持不变。原四项的顺序和通知 ID 保留，新增项位于页面末尾，清除按钮覆盖全部六项。未自动触发通知，`fitStart` 的真机显示待用户手动确认。
